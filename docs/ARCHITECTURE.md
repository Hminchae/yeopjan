# 옆잔 아키텍처

## 원칙

서버가 사용자, 현재 위치, 좌석, 채널, 채팅 작성자, 접속 상태의 유일한 권위다. 클라이언트는 의도를 전송하고 서버가 확정한 스냅샷 또는 이벤트만 렌더링한다.

## 저장소 구조

```text
apps/
  server/      Fastify, Socket.IO, SQLite, 운영자 API
  web/         React, Vite, Three.js 장면, 모바일 UI
packages/
  shared/      Zod 스키마, 이벤트와 도메인 타입, 좌석 정의
tests/
  e2e/         Playwright 단일·다중 브라우저 검증
docs/          제품, 아키텍처, 계획, 운영·법적 검토
```

pnpm workspace와 TypeScript strict mode를 사용한다. 핵심 의존성은 React, Vite, Three.js, Fastify, Socket.IO, Zod, SQLite 드라이버, Vitest, Playwright다. UI는 코드 기반 3D 지오메트리·재질·파티클로 그려 외부 게임 그래픽을 복제하지 않는다.

## 런타임

```text
React UI <-> scene adapter <-> Three.js WebGL scene
    |                           |
    +------- socket client -----+
                 |
          Fastify + Socket.IO
                 |
       authoritative BarState
                 |
       SQLite reports / bans
```

개발 환경에서는 Vite가 API와 Socket.IO를 Fastify 포트로 프록시한다. 프로덕션에서는 Fastify가 빌드된 웹 파일과 같은 origin의 Socket.IO를 제공한다. 이 구성은 CORS와 세션 노출 면적을 줄이고 Docker 컨테이너 하나로 재현한다.

## 도메인 상태

메모리의 `BarState`가 현재 바 상태를 보관한다.

- `users`: 공개 ID, 닉네임, 아바타, 기분, 위치, 좌석, 음료, 채널
- `seats`: 좌석 ID에서 공개 사용자 ID로의 점유 맵
- `sessions`: 비공개 재접속 토큰 해시에서 현재 소켓·사용자 상태로의 맵
- `channels`: `counter`, `table-1`, `table-2`; 창가와 바닥은 채팅 없음
- `cooldowns`: 채팅, 위치, 건배, 반응, 신고의 서버 측 토큰 버킷

공개 이벤트에는 IP, 원본 세션 토큰, 소켓 ID, 신고자 정보가 들어가지 않는다.

## 입장과 재연결

1. 랜딩의 접속 인원은 서버의 공개 presence endpoint와 Socket.IO presence 이벤트에서 온다.
2. 입장 요청을 Zod로 검증한 뒤 서버가 공개 사용자 ID와 httpOnly이 아닌 브라우저 저장용 불투명 재접속 토큰을 발급한다. 토큰은 서버에서 해시로만 비교한다.
3. 같은 재접속 토큰으로 새 소켓이 연결되면 이전 소켓을 교체해 중복 존재를 막는다.
4. 짧은 단절은 Socket.IO connection state recovery를 사용하되 미들웨어를 건너뛰지 않는다.
5. 연결 또는 복구 뒤 서버 전체 공개 스냅샷을 보내 누락 이벤트를 보정한다.
6. 명시적 퇴장 또는 복구 유예 만료 시 좌석과 사용자를 제거하고 presence를 갱신한다.

브라우저 저장소의 토큰은 익명 세션 복원용이며 계정 인증 수단이 아니다. XSS 방지를 위해 React 텍스트 렌더링만 사용하고 CSP를 설정한다.

## 좌석과 이동

좌석 요청은 한 Node 이벤트 루프의 동기 임계 구역에서 `빈 좌석 확인 -> 기존 좌석 해제 -> 새 좌석 점유 -> 사용자 갱신` 순으로 처리한다. 두 요청이 같은 좌석에 도착해도 첫 요청만 성공한다. 클라이언트는 성공 응답 전 착석을 확정하지 않는다.

자유 이동 좌표는 장면 경계와 최대 이동 거리를 서버에서 제한한다. 이동 이벤트은 100ms 단위로 제한하고, 렌더러는 서버 위치 사이를 보간한다. 좌석 선택은 미리 정의된 좌표만 허용한다.

## 채널 격리

좌석 변경 때 서버가 기존 Socket.IO room을 떠나고 새 채널 room에 가입시킨다. 메시지는 현재 사용자 채널을 서버에서 조회해 작성자를 덮어쓰고 해당 room에만 송신한다. 클라이언트가 보낸 채널이나 작성자 ID는 신뢰하지 않는다.

## 안전과 운영

- 모든 이벤트 payload를 공유 Zod 스키마로 검증한다.
- 닉네임과 채팅은 길이·제어문자·공백을 정규화하고 React가 텍스트로 렌더링한다.
- 토큰 버킷으로 소켓별·세션별 빈도를 제한한다.
- 음소거·차단 목록은 클라이언트와 서버 세션 상태에 두고 송신 대상을 필터링한다.
- 신고와 제재는 SQLite에 저장한다. 신고 원문은 30일 뒤 삭제하는 정리 작업을 둔다.
- 운영자 API는 `ADMIN_TOKEN`의 constant-time 비교로 보호하고 프로덕션에서 미설정 시 비활성화한다.
- 운영자는 공개 사용자 ID 또는 세션 해시를 일정 기간 제재할 수 있다. 비밀은 환경 변수로만 주입한다.

## 접근성과 성능

장면과 모든 핵심 동작에는 DOM 기반 이름과 버튼을 제공한다. 색만으로 상태를 전달하지 않고 포커스 표시, 44px 터치 타깃, 라이브 영역을 제공한다. 소리는 기본 OFF다. `prefers-reduced-motion`에서는 비, 조명, idle, 이동 보간, 건배 파티클을 정적 또는 즉시 전환으로 낮춘다. 저사양 모드는 파티클 수와 렌더 해상도를 제한한다.

## 확장 지점

정원 초과 시 `BarRegistry`가 가장 덜 찬 바 인스턴스를 선택하도록 인터페이스만 분리한다. 다중 프로세스가 필요해지면 인메모리 `BarState`를 외부 상태 저장소로 옮기고 Socket.IO Redis Adapter를 붙인다. MVP에는 Redis, 메시지 브로커, Kubernetes를 넣지 않는다.
