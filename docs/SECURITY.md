# 보안과 운영 기준

## 위협 모델

옆잔은 가입 없는 익명 채팅 서비스이므로 신원 도용보다 세션 탈취, 반복 입장, 메시지 폭주, 괴롭힘, 채널 누출, 입력 주입, 운영자 API 노출을 우선 위협으로 본다. 클라이언트가 보내는 닉네임, 좌표, 좌석, 음료, 채팅, 반응, 신고, 재접속 토큰은 모두 신뢰하지 않는다.

## 연결 경계

- 프로덕션은 HTTPS/WSS만 허용한다.
- WebSocket handshake의 `Origin`을 `ALLOWED_ORIGINS`의 완전 일치 목록으로 검사한다.
- Socket.IO 최대 payload를 16KiB로 제한하고 전송 압축은 끈다.
- 재접속 토큰은 URL에 넣지 않고 Socket.IO auth payload로 전달한다.
- 토큰은 로그와 공개 이벤트에 기록하지 않고 서버에서는 SHA-256 해시로만 인덱싱한다.
- 토큰 하나에는 활성 소켓 하나만 허용하고 새 연결이 기존 연결을 교체한다.
- ping timeout과 복구 유예가 끝난 연결은 사용자, 좌석, room을 정리한다.

## 이벤트 권한

| 이벤트 | 서버가 검증·결정하는 값 |
|---|---|
| 입장 | 닉네임, 아바타, 기분, 정원, 제재 상태, 공개 ID |
| 이동 | 현재 사용자, 경계, 최대 거리, 빈도, 확정 좌표 |
| 착석 | 좌석 존재, 점유, 현재 좌석 해제, 채널 |
| 채팅 | 작성자, 현재 채널, 길이, 빈도, 차단 수신자 |
| 건배·반응 | 작성자, 현재 채널, 종류, cooldown |
| 신고 | 신고자 세션, 대상 존재, 사유, 빈도, 저장 범위 |

클라이언트가 전송한 작성자 ID, room, 좌석 점유 결과는 무시한다. 모든 이벤트는 ack로 성공 또는 기계 판독 가능한 오류 코드를 반환한다.

## 입력과 출력

- Zod 스키마가 타입, 열거값, 길이, 숫자 범위를 검사한다.
- 사용자 문자열은 Unicode를 허용하되 NUL과 제어 문자를 제거하고 연속 공백을 줄인다.
- 채팅은 서식 없는 텍스트만 지원한다. HTML을 저장하거나 렌더링하지 않는다.
- React의 기본 텍스트 이스케이프를 사용하며 `dangerouslySetInnerHTML`, `innerHTML`, `eval`, 동적 URL을 사용하지 않는다.
- 기본 CSP는 같은 origin의 스크립트·스타일·이미지·연결만 허용하고 object, frame, 외부 form을 막는다.

## 속도와 자원 제한

초기 제한값은 보수적으로 두며 실제 운영 지표로 조정한다.

| 동작 | 제한 |
|---|---|
| 채팅 | 5회 / 10초, 최대 300자 |
| 이동 | 10회 / 초 |
| 착석 | 4회 / 5초 |
| 건배 | 1회 / 3초 |
| 반응 | 4회 / 5초 |
| 음료 변경 | 6회 / 5초 |
| 차단 전환 | 6회 / 10초 |
| 신고 | 3회 / 시간 |
| 입장 | 세션당 활성 사용자 1명 |

제한은 입장 후 소켓 ID가 아니라 세션 해시 기준으로 계산한다. Socket.IO의 16KiB 최대 payload와 동작별 제한을 함께 적용한다.

## 음소거, 차단, 신고

- 음소거는 특정 사용자의 말풍선·채팅 알림을 로컬에서 숨긴다.
- 차단은 서버가 차단한 사용자의 채팅·건배·반응을 해당 수신자에게 보내지 않게 한다.
- 신고는 대상 공개 ID, 사유 코드, 선택적 설명, 관련 메시지 텍스트, 시각만 저장한다.
- 신고자 원본 토큰과 IP는 저장하지 않고 신고자 세션의 일방향 해시만 중복 방지에 사용한다.
- 신고 자료는 기본 30일 뒤 삭제한다. 법적 보존 요청이 필요한 경우 별도의 운영 절차를 먼저 승인해야 한다.

## 운영자 경계

- `/api/admin/*`는 서버 환경 변수 `ADMIN_TOKEN`이 있을 때만 활성화한다.
- Bearer token은 constant-time 비교하고 실패 응답은 세부 원인을 구분하지 않는다.
- 운영 작업은 공개 사용자 ID 제재, 세션 해시 제재, 제재 해제, 신고 목록 확인으로 제한한다.
- 운영자 token, 세션 token, IP, 전체 채팅 내용은 일반 로그에 남기지 않는다.
- 클라이언트 번들과 `VITE_*` 환경 변수에는 운영 비밀을 넣지 않는다.

## 로그

접속·종료, Origin 거절, 검증 실패의 이벤트명, 속도 제한, 신고 생성, 운영자 작업의 결과를 구조화해 기록한다. 사용자 메시지 본문과 토큰은 기록하지 않는다. 운영 전 로그 접근 권한, 보관 기간, 삭제 절차를 확정해야 한다.

## 자동화 보안 검증

- 허용되지 않은 Origin의 Socket.IO 연결 거절
- 잘못된 타입, 초과 길이, 과대 payload 거절
- `<script>`와 이벤트 핸들러 문자열이 실행되지 않고 텍스트로 표시됨
- 다른 room 메시지와 이벤트 비수신
- 동일 토큰 재접속 시 중복 사용자 부재
- 속도 제한과 cooldown 오류 코드
- 차단 사용자의 이벤트 비수신
- 인증 없는 운영 API와 틀린 token 거절
- 프로덕션 웹 번들에서 `ADMIN_TOKEN`과 테스트 비밀 문자열 부재
- 신고 보관 기한 정리

## 공개 전 차단 항목

- 실제 도메인 기준 `ALLOWED_ORIGINS`, TLS 종료, 프록시 WebSocket upgrade 설정
- 운영자 token의 비밀 저장소 주입과 교체 절차
- 개인정보 처리방침, 커뮤니티 가이드라인, 신고 대응 담당자
- 로그·신고 데이터의 저장 위치, 접근 통제, 백업, 삭제 검증
- 부하 시험으로 동시 연결 상한과 메모리 사용량 확인
